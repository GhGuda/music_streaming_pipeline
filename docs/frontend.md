# KPI Dashboard

A lightweight, zero-build-step web dashboard that surfaces the pipeline's computed KPIs in real time.

## Architecture

```
Browser
  └── S3 static website  (index.html · app.js · styles.css · config.js)
        └── API Gateway HTTP API  (/dates · /daily · /top-genres · /top-songs)
              └── Lambda  kpi_api/handler.py  (read-only DynamoDB queries)
                    └── DynamoDB  music-streaming-<env>-kpis
```

The dashboard is a single HTML page with vanilla JS. Three static files are uploaded to an S3 bucket configured as a public-read website. A fourth file (`config.js`) is generated by Terraform at deploy time and injects the API Gateway URL so no manual configuration is needed.

Provisioned by `infra/modules/dashboard/main.tf`, wired into the dev environment via `infra/envs/dev/main.tf`.

## Accessing the Dashboard

Deploy or refresh the dashboard resources:

```bash
terraform -chdir=infra/envs/dev init
terraform -chdir=infra/envs/dev plan -out plan.tfplan
terraform -chdir=infra/envs/dev apply plan.tfplan
```

Then get the browser URL from Terraform:

```bash
terraform -chdir=infra/envs/dev output -raw dashboard_url
```

Navigate to that URL in a browser. The dashboard fetches all available dates from the API on startup and renders KPIs for the most recent one.

For API smoke tests, Terraform also exposes the API Gateway base URL:

```bash
terraform -chdir=infra/envs/dev output -raw dashboard_api_endpoint
```

Do not use the local `dashboard/index.html` file as the deployed URL. The browser app depends on a generated `config.js` file that Terraform renders from `dashboard/config.js.tpl` and uploads to S3 with the deployed API Gateway URL.

## UI Sections

| Section | Description |
|---|---|
| **Summary cards** | Total listens, unique listeners, total listening time (hours), genre count for the selected date |
| **Daily Genre KPIs** | Full table — listen count, unique listeners, total time, avg time/user — one row per genre, sorted by listen count |
| **Top Genres** | Ranked list of the 5 most-listened genres for the selected date |
| **Top Songs** | Ranked top-3 tracks for the genre currently selected in the Genre dropdown |

## Controls

| Control | Behaviour |
|---|---|
| **Date** dropdown | Populated from all dates present in DynamoDB. Selecting a new date reloads all sections. |
| **Genre** dropdown | Populated from the genres returned for the selected date. Selecting a genre reloads Top Songs only. |
| **Refresh** button | Re-fetches the date list then reloads KPIs — useful after a new pipeline run completes. |

## API Endpoints

All endpoints are served through API Gateway HTTP API (v2). The base URL is injected into `config.js` by Terraform.

### `GET /dates`

Returns all dates that have KPI records in DynamoDB, sorted newest first.

```json
{
  "dates": ["2024-06-25", "2024-06-24"]
}
```

### `GET /daily?date=YYYY-MM-DD`

Returns all `DAILY_GENRE_KPI` items for the date, sorted by listen count descending.

```json
{
  "date": "2024-06-25",
  "items": [
    {
      "pk": "DATE#2024-06-25",
      "sk": "GENRE#dance",
      "record_type": "DAILY_GENRE_KPI",
      "date": "2024-06-25",
      "genre": "dance",
      "listen_count": 150,
      "unique_listeners": 150,
      "total_listening_time_seconds": 29340.0,
      "avg_listening_time_per_user_seconds": 195.6,
      "gsi1pk": "GENRE#dance",
      "gsi1sk": "DATE#2024-06-25",
      "updated_at": "2026-06-25T21:33:30Z"
    }
  ]
}
```

### `GET /top-genres?date=YYYY-MM-DD`

Returns the `TOP_5_GENRES` item for the date.

```json
{
  "date": "2024-06-25",
  "item": {
    "pk": "DATE#2024-06-25",
    "sk": "TOP_GENRES",
    "record_type": "TOP_5_GENRES",
    "date": "2024-06-25",
    "top_genres": [
      { "rank": 1, "genre": "dance",      "listen_count": 150 },
      { "rank": 2, "genre": "anime",      "listen_count": 148 },
      { "rank": 3, "genre": "black-metal","listen_count": 148 },
      { "rank": 4, "genre": "club",       "listen_count": 142 },
      { "rank": 5, "genre": "country",    "listen_count": 142 }
    ],
    "updated_at": "2026-06-25T21:33:30Z"
  }
}
```

### `GET /top-songs?date=YYYY-MM-DD&genre=<genre>`

Returns the `TOP_3_SONGS_BY_GENRE` item for the (date, genre) pair.

```json
{
  "date": "2024-06-25",
  "genre": "dance",
  "item": {
    "pk": "DATE#2024-06-25",
    "sk": "GENRE#dance#TOP_SONGS",
    "record_type": "TOP_3_SONGS_BY_GENRE",
    "date": "2024-06-25",
    "genre": "dance",
    "top_songs": [
      { "rank": 1, "track_id": "...", "track_name": "Track Name", "artists": "Artist", "listen_count": 12 },
      { "rank": 2, "track_id": "...", "track_name": "Track Name", "artists": "Artist", "listen_count": 10 },
      { "rank": 3, "track_id": "...", "track_name": "Track Name", "artists": "Artist", "listen_count": 9 }
    ],
    "updated_at": "2026-06-25T21:33:30Z"
  }
}
```

**Error responses** — all endpoints return `{"error": "..."}` with an appropriate HTTP status code (400, 404, 500).

## Source Files

| File | Purpose |
|---|---|
| `dashboard/index.html` | HTML shell — header, filter controls, summary cards, genre table, top-genres and top-songs lists |
| `dashboard/styles.css` | All styling — summary cards, data table, ranked lists |
| `dashboard/app.js` | Fetch calls, DOM rendering, event listeners — no framework dependencies |
| `dashboard/config.js.tpl` | Terraform template; rendered as `config.js` in S3 with `window.DASHBOARD_CONFIG = { apiBaseUrl: "..." }` |

Editing any of these files and running `make apply` redeploys them automatically — Terraform tracks changes by file MD5 hash.

## Lambda — `lambda/kpi_api/handler.py`

Read-only Lambda (Python 3.11, 15 s timeout). Behaviour per route:

| Route | DynamoDB operation |
|---|---|
| `/dates` | `scan` projecting only `date`; deduplicates and returns sorted |
| `/daily` | `query` on `pk = DATE#<date>`, filter `record_type = DAILY_GENRE_KPI` |
| `/top-genres` | `get_item` for `pk = DATE#<date>`, `sk = TOP_GENRES` |
| `/top-songs` | `get_item` for `pk = DATE#<date>`, `sk = GENRE#<genre>#TOP_SONGS` |

`Decimal` values from DynamoDB are serialised as `int` if whole, `float` otherwise. CORS headers (`Access-Control-Allow-Origin: *`) are set on every response, and `OPTIONS` preflight requests return 204.

## Infrastructure Resources

| Terraform resource | Purpose |
|---|---|
| `aws_s3_bucket` | Hosts the static website — public-read bucket policy, no KMS (static assets are not sensitive) |
| `aws_s3_bucket_website_configuration` | Enables S3 website hosting; `index.html` as root document |
| `aws_s3_object` × 4 | Uploads `index.html`, `styles.css`, `app.js`, and the rendered `config.js` |
| `aws_lambda_function` (kpi_api) | Read-only query handler |
| `aws_apigatewayv2_api` | HTTP API with built-in CORS |
| `aws_apigatewayv2_route` × 4 | Routes `/dates`, `/daily`, `/top-genres`, `/top-songs` to Lambda |
| `aws_apigatewayv2_stage` | `$default` stage with `auto_deploy = true` |
| `aws_lambda_permission` | Grants API Gateway permission to invoke the Lambda |

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| "Dashboard API URL is not configured" | `config.js` missing or `window.DASHBOARD_CONFIG` not set | Re-run `make apply`; verify `aws_s3_object.config` was uploaded |
| Blank page / network errors in console | Wrong `apiBase` in `config.js` or CORS misconfiguration | Check `terraform output dashboard_url`; verify API GW CORS settings |
| "No KPI dates found yet" | Pipeline has not run successfully, or DynamoDB is empty | Run the pipeline; query DynamoDB to confirm items exist |
| Lambda returns 500 | Missing `DYNAMODB_TABLE` env var or Lambda lacks DynamoDB permissions | Check Lambda env in console; verify `lambda_policy.json` includes `dynamodb:Query`, `dynamodb:GetItem`, `dynamodb:Scan` |
| Dashboard URL returns 403 | S3 bucket policy not applied or `block_public_policy = false` not set | Check S3 bucket policy in console; re-run `make apply` |
